# Cake Sort — Кондитерская

3D-головоломка на Three.js. **Игровой стол 3×3, выдача — 5 тарелок.**
Перетащите тарелку из выдачи на свободную ячейку мраморного стола —
совпадающие кусочки перелетают между тарелками **сами**, в том числе
**цепочкой через соседние тарелки**. Шесть одинаковых сегментов на
тарелке складываются в целый торт: он надевает корону, улетает на
золотую подставку, а ячейка освобождается.

Кусочки игрок вручную не переносит; тарелки на поле после размещения
неподвижны.

## Механика очков (итерация 3)

Собираем не «N тортов», а **N очков**:

- **Торт — 100 очков**, каждый следующий торт за один ход — **+25**
  (комбо). Каждый перелетевший кусочек — **2 очка**.
- Над столом — **прогрессбар до нового торта**: золотая полоса с числом
  очков и иконкой следующего торта на конце (крупнее самой полосы).
- При достижении цели уровень пройден: **эффектная карточка с новым
  тортом** (SVG-вид сверху, блик, свечение) — торт открыт и появится
  в игре на следующем уровне. Всего 16 видов; когда открыты все —
  начинается **золотая серия**: карточки с золотыми тортами.
- Очки за торт всплывают над ячейкой («+100», «Комбо ×2!»).
- **Поражение одно**: стол 3×3 забился до отказа. Проиграть «намертво»
  невозможно — выдача бесконечна, вопрос лишь в мастерстве.

## Правило соседних тарелок (цепочки)

Торты собираются на соседних тарелках:

- **Прямой перенос.** У двух коснувшихся тарелок есть одинаковые вкусы —
  кусочки перелетают к той тарелке, где этого вкуса больше.
- **Цепочка.** Кусочек может долететь и до дальней тарелки: он «прыгает»
  по маршруту через промежуточные тарелки, **если на каждой из них есть
  свободное место**. Полная тарелка маршрут блокирует. Ставьте тарелки
  так, чтобы маршруты собирали вкус в одном месте — это и есть головоломка.
- Опустевшая тарелка исчезает и освобождает ячейку; собранный торт
  улетает на подставку.

### Дальность цепочки — параметр сложности (Этап B)

Аудит Этапа A показал: на поле 3×3 неограниченные цепочки делают
размещение малозначимым — кусочки сами стекаются через пол стола
(«аккумуляторный эффект»). Поэтому дальность маршрута задана
**конфигурацией уровня**:

- **Уровни 1–5 (обучение)** — цепочки без ограничения: длинные
  эффектные маршруты знакомят с правилом.
- **С уровня 6** — **два прыжка** (донор → один транзит → получатель).
  Дальние вкусы собираются вручную, из коротких сегментов — выбор места
  и маршрута становится головоломкой.

Проверено симулятором (`scripts/tune-targets.ts`): жадный игрок
проходит все уровни, случайный выигрывает ~43% — проигрывать можно, но
это не «стена».

## Конфигурация цепной реакции (Этап B)

Разрешение хода вынесено в настраиваемый конфиг
(`CascadeConfig` в `game/types.ts`):

```ts
interface CascadeConfig {
  maxResolutionSteps: number;   // защитный лимит шагов (по умолчанию 64)
  maxTransfersPerTurn: number;  // по умолчанию ∞ — отключено
  maxCakesPerTurn: number;      // по умолчанию ∞ — отключено
  allowChainTransfers: boolean; // выкл — ломает проходимость (аудит V3)
  maxChainHops: number;         // дальность цепочки; ∞ = без ограничения
  directTransferPriority: boolean;
}
```

Лимиты переносов и тортов выключены: замеры аудита показали, что они
лишь откладывают сборки и порождают патологию «шесть кусочков, но торт
не собирается». `maxResolutionSteps` — страховка (доказанный максимум —
54 шага); при срабатывании ход завершается безопасно, состояние остаётся
консистентным, в журнал пишется снимок поля для диагностики.

Разрешение хода возвращает **журнал событий** (`resolveTurnLogged` →
`TurnEvent[]`: `place / transfer / cake / plateGone / phase / aborted`):
игровое состояние считается полностью и независимо от анимаций
(ТЗ 3.7), а визуальный слой воспроизводит журнал **волнами** — события,
не пересекающиеся по тарелкам, анимируются одновременно. Серию
«торт за тортом» ускоряет темп (~2.4 → 1.6 → 1.1 с), получатель
цепочки подсвечивается золотым контуром.

## Возможности

- **Стол 3×3, выдача 5**: слоты выдачи раскладываются динамически —
  двойная тарелка занимает два слота и её половинки **полноразмерные,
  как обычные тарелки**.
- **Бесконечный поток выдачи**: детерминированный (seed = f(номер
  уровня, позиция в потоке)) — у всех игроков одинаковые тарелки.
  Состав: на тарелке 2–3 вкуса (4 — редкость), «полторта» одним вкусом
  не выдаётся, чистые тарелки 1–2 кусочка и редкие «почти торты» (5
  одинаковых) — подарок.
- **Прогрессия тортов**: уровень n играет вкусами из пула (максимум 6,
  всегда включая новинку); прохождение открывает следующий торт.
- **Двойная тарелка** (с уровня 3, не чаще одной в выдаче): две
  полноразмерные тарелки с золотой перемычкой, ставится целиком на две
  соседние ячейки; «Повернуть двойную тарелку» (или R) вращает на 90°,
  хода не тратит. После размещения половинки живут самостоятельно.
- **Монеты и подсказка** — +10 за уровень, «Подсказка −15» подсвечивает
  лучший ход (жадная оценка на шаг вперёд: очки, прогресс тарелок к
  торту, соседства, свободные ячейки). Прогресс и монеты — в localStorage.
- **Мобильные устройства** (VK Игры / РуStore): Pointer Events,
  портретная ориентация, safe-area, кнопки ≥ 44 px, адаптивная камера;
  прогрессбар на узких экранах — отдельной строкой под HUD.

## Запуск

```bash
npm install
npm run dev        # дев-сервер: http://localhost:5173
```

Продакшен-сборка и тесты:

```bash
npm run build      # tsc + vite build → dist/
npm run preview    # локальный сервер поверх dist/
npm test           # автотесты игрового слоя (scripts/pz-tests.ts)
```

Автотесты не требуют браузера: очки и комбо, победа по цели, кривая
сложности, открытие тортов, детерминизм потока, состав тарелок, окно
выдачи 5, **проходимость жадным игроком уровней 1–25** (никаких
«застрявших» уровней), двойная тарелка, прямые переносы, **цепочки**
(маршрут, блокировка полным транзитом, ограничение по месту,
направление, маршрут по периметру 3×3) и конец партии; **секция 9 —
Этап B**: эквивалентность журнала событий старому алгоритму, детерминизм
журнала, границы maxChainHops (1/2/3/∞, углы и диагонали), транзит через
свободное место при всех дальностях, безопасная остановка
maxResolutionSteps, освобождение донора в том же ходу, комбо, победа по
последнему торту хода, двойная тарелка в журнале, прогрессия
maxChainHops из конфига уровня.

Инструменты баланса (без браузера, те же правила):

```bash
npx tsx scripts/tune-targets.ts   # калибровка кривой целей и дальности цепочки
npx tsx scripts/audit-cascade.ts  # аудит Этапа A (воспроизводит его числа)
```

## Управление

Нажмите на тарелку в нижней выдаче и, не отпуская, тащите её на поле.
Свободная ячейка подсвечивается золотым кольцом (для двойной — оба
кольца пары). Отпустите над ячейкой — тарелка встанет, запустится
автосортировка с анимацией цепочки. Отпустите мимо поля — тарелка
вернётся в выдачу, ход не расходуется.

Кнопки: «Подсказка −15», «Заново» и «Повернуть двойную тарелку»
(появляется, только когда двойная видна в выдаче; на ПК также R).
Пока идут переносы и сборка тортов, ввод заблокирован.

Победа — набрать цель уровня в очках. Поражение — стол заполнен
(в том числе когда в видимой выдаче только двойные, а свободные ячейки
не образуют соседних пар).

## Архитектура (4 слоя)

```
index.html                     — страница игры (HUD, прогрессбар до
                                 нового торта, карточка победы, тосты)
src/puzzle/game/types.ts       — слой 1: данные (GState с очками и
                                 комбо, TrayItem, Transfer с маршрутом
                                 цепочки, TrayStream, CascadeConfig,
                                 TurnEvent-журнал)
src/puzzle/game/rules.ts       — слой 2: правила (соседство, прямые
                                 переносы, цепочки через транзитные
                                 тарелки BFS-маршрутом с лимитом
                                 дальности, размещения, очки/комбо,
                                 resolveTurnLogged — фазовое разрешение
                                 с журналом событий, конец партии,
                                 bestMove для подсказки) — чистый TS
src/puzzle/game/generator.ts   — слой 2: конфиг уровня (цель, пул
                                 вкусов, открытие тортов, прогрессия
                                 maxChainHops) и детерминированный
                                 бесконечный поток
src/puzzle/game/levels.ts      — слой 2: getLevel(n) → buildLevel(n)
src/puzzle/engine.ts           — слои 3–4: Three.js-сцена, drag&drop,
                                 динамическая выдача на 5, двойная
                                 тарелка, воспроизведение журнала
                                 событий волнами, анимация перелётов
                                 по маршруту цепочки, GSAP, камера
src/puzzle/cakes.ts            — 16 видов тортов, 3D-модели тарелок,
                                 стола, подставки, короны, перемычки
src/puzzle/sfx.ts              — WebAudio-синтезатор звуков
src/puzzle/main.ts             — точка входа: HUD, прогрессбар,
                                 карточка нового торта, всплывающие
                                 очки, монеты, туториалы уровней 1–4
scripts/pz-tests.ts            — автотесты игрового слоя (npm test)
scripts/tune-targets.ts        — калибровка кривой целей и прогрессии
                                 maxChainHops (симулятор Этапа B)
scripts/audit-cascade.ts       — аудит цепной реакции (Этап A;
                                 воспроизводит числа отчёта)
docs/AUDIT-STAGE-A.md          — отчёт аудита Этапа A
```

Игровые правила не зависят от Three.js и GSAP: слой `game/` тестируется
в Node.

## Технологии

Vite + TypeScript (strict) + Three.js + GSAP; тесты — tsx. Никакого
физического движка: перемещения тарелок и кусочков — лёгкие твины.
